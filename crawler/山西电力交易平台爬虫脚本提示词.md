# 山西电力交易平台爬虫脚本提示词

## 1. 爬虫目标

开发一个自动化爬虫脚本，用于爬取**山西电力交易平台**电力现货市场信息披露网站上的所有表格数据。

**目标网站基础信息：**
- **URL：** `https://pmos.sx.sgcc.com.cn/#/dashboard`
- **平台名称：** 山西电力交易中心 电力交易平台（SXPX）
- **应用类型：** 单页应用（SPA），使用 hash 路由 `#/dashboard`

### 1.1 现货出清结果
- 实时市场出清概况
- 日前市场出清概况
- 日前备用总量

### 1.2 现货实时数据
- 实时各时段出清现货电量
- 实时备用总量
- 实时节点边际电价
- 实时输电断面约束及阻塞
- 断面约束情况及影子价格
- 重要通道实际输电情况
- 机组实际发电曲线

### 1.3 现货日前信息
- 抽蓄电站水位
- 断面约束
- 日前联络线计划
- 输变电设备检修计划
- 输电通道可用容量
- 日前机组开机安排
- 日前节点边际电价
- 日前正负备用需求

### 1.4 综合查询 - 供需与约束 - 参数信息
- 节点分配因子

**导航路径说明（3 层树形菜单 — el-tree 控件）：**
- 左侧栏使用 **Element UI 的 el-tree（树形控件）** 渲染，NOT el-menu
- **DOM 结构**：`#leftMenuTwo > #guide-menu > .el-tree.filter-tree > div[role="treeitem"].el-tree-node`
- 菜单文本在 `<span title="菜单名">菜单名</span>` 中，使用 `title` 属性精确标识
- 可点击区域为 `.el-tree-node__content`，展开图标为 `.el-tree-node__expand-icon`
- 展开状态通过 `aria-expanded="true"` 和 `is-expanded` class 判断
- 叶子节点的 expand-icon 有 `is-leaf` class
- 导航到具体数据页面需依次展开 3 层：
  1. 第一层（父节点）：展开**「信息披露」**树节点
  2. 第二层（分类节点）：在信息披露下展开**「现货出清结果/现货实时数据/现货日前信息/综合查询」**
  3. 第三层（叶子节点）：点击具体数据页面（如「日前备用总量」）
- 完整路径示例：`信息披露 > 现货出清结果 > 日前备用总量`
- 综合查询下路径更深：`信息披露 > 综合查询 > 供需与约束 > 参数信息 > 节点分配因子`
- 树形菜单为**点击切换**（toggle）模式，重复点击会收起，**必须检查 `aria-expanded` 属性避免误操作**
- 面包屑可验证路径：页面顶部显示 `当前位置：首页 > 信息披露 > {分类} > {页面}`

**综合查询特殊导航说明：**
- 「综合查询」在侧边栏中是**叶子节点**（点击后打开独立 Web 页面），NOT 可展开的分支
- 打开后的页面有**自己独立的导航结构**（与侧边栏的 el-tree 无关）：
  - **顶部导航栏**：水平可滚动标签页（供需与约束、电网运行、市场运营 等）
  - **左侧面板**：手风琴/可展开菜单（约束信息、参数信息 等）
  - 叶子项：点击后加载数据页面
- 综合查询页面内容可能渲染在 iframe 中，需在主页面和 iframe 中同时搜索元素（精确匹配优先，回退到包含匹配）

## 2. 页面架构与 iframe 结构（重要）

该平台使用 iframe 加载各个功能页面内容，这是脚本开发的核心难点：

### 2.1 iframe 嵌套结构

平台存在**两种 iframe 结构**：

1. **二层结构**（Element UI 页面）：
   ```
   主页面（侧边栏菜单 + tab 切换）
     └── 内容 iframe（日期筛选、表格、导出按钮等 Element UI 控件）
   ```

2. **三层结构**（FineReport 报表页面）：
   ```
   主页面
     └── 中间 iframe（通常 id="pxf-settlement-outnetpub"）
           └── 内层 iframe（通常 id="iframe"，包含 FineReport 表单控件）
   ```

### 2.2 iframe 上下文切换

- 导航到目标页面后，必须检测 iframe 并将所有 handler 的操作上下文（`ctx`）切换到 iframe 内部
- 主页面（`page`）用于侧边栏导航和键盘操作（`keyboard.press`）
- iframe 中的 `Frame` 用于查找日期输入框、下拉框、查询/导出按钮、表格等控件
- iframe 可能因页面重新渲染、Vue 路由切换等原因被替换，旧的 Frame 引用变为 detached 状态，需要重新检测

### 2.3 iframe 有效性检测

- 通过 `frame.evaluate("() => document.readyState")` 验证 Frame 是否仍然有效
- 检测到 detached 后自动重新扫描 iframe 并切换上下文
- 重试机制：内层 iframe 可能延迟加载，需多次重试穿透嵌套结构

### 2.4 页面自动刷新恢复

- 平台可能在长时间操作（如导出等待）期间自动刷新页面或会话超时
- 通过比较 `_current_iframe_id` 与 `_task_iframe_id`（首次导航时记录）检测页面跳转
- 若检测到页面被刷新回首页，自动重新导航到目标页面并恢复 iframe 上下文

## 3. 两种页面类型适配

### 3.1 Element UI 页面

**特征控件：**
- `.el-date-editor`（日期选择器）
- `.el-select`（下拉框，面板挂载在 `<body>` 上，非控件内部）
- `.el-form-item`（表单项容器）
- `<button>` 元素（查询/导出按钮）
- `.el-pagination`（分页组件）
- 标准 HTML `<table>` + `<thead>` / `<tbody>` 结构

**代表页面：** 实时节点边际电价、日前节点边际电价、日前机组开机安排等

### 3.2 FineReport 报表页面

**特征控件：**
- `.fr-trigger-editor`（日期/下拉控件，使用 `widgetname` 属性标识）
- `.fr-form-imgboard`（按钮控件）
- `.para-container`（参数面板容器）
- `input.fr-trigger-texteditor`（输入框）
- `button.fr-btn-text.x-emb-excel`（导出按钮）
- `div[widgetname^="SEARCH"]`（查询按钮，widgetname 以 SEARCH 开头）
- `table.x-table` 或包含 `REPORT` class 的表格，使用 `tridx` 属性标识行

**FineReport JS API：**
- `_g()` 获取报表对象
- `_g().parameterEl.getWidgetByName(name)` 获取参数面板控件
- `widget.getItems()` 获取 combo 控件的选项列表
- `widget.setValue(value)` 设置控件值
- `_g().gotoPage(n)` 跳转到指定页码
- `_g().currentPage` / `_g().totalPage` 获取当前页码和总页数

**代表页面：** 抽蓄电站水位、断面约束、日前备用总量、实时备用总量等

### 3.3 页面类型自动检测

所有 handler（筛选、导出、分页、数据提取）均内置页面类型检测逻辑：
- 检测 `.fr-trigger-editor` / `.fr-form-imgboard` / `.para-container` 的存在来判断是否为 FineReport 页面
- 根据检测结果自动选择对应的操作策略

## 4. 爬虫功能要求

### 4.1 数据获取

#### 4.1.1 浏览器与访问
- **运行环境：** 服务器上已有 Chrome 浏览器处于打开状态，且已通过登录认证进入系统首页
- **连接方式：** 脚本通过 **Chrome DevTools Protocol (CDP)** 连接到已有 Chrome，直接操作已打开的页面，不启动新浏览器、不重新登录
  - Chrome 需以 `--remote-debugging-port=9222` 参数启动
  - 脚本通过 CDP 连接后查找包含 `pmos.sx.sgcc.com.cn` 的标签页
  - 脚本结束后只断开连接，不关闭浏览器
- **备用模式（launch）：** 启动全新 Chromium 实例（用于本地调试），无图形环境时自动切换无头模式
- 处理单页应用（SPA）的动态加载，在导航、筛选、查询后增加显式等待

#### 4.1.2 导航与筛选

**导航流程：**
- 通过左侧栏 el-tree 树形菜单自动定位并访问各数据类别页面
- 导航后检测 iframe 并切换操作上下文到 iframe 内部
- 等待 iframe 加载完成（包括嵌套 iframe 的穿透）
- 综合查询页面使用独立导航结构（顶部标签页 + 左侧面板）

**筛选条件处理：**
- **日期**：`YYYY-MM-DD` 格式，绝大多数页面仅支持**单日期**选择
  - 自动适配 Element UI DatePicker / FineReport 日期控件 / 通用 input
  - 多层回退定位策略：预定义选择器 → 表单标签定位 → 父级遍历 → 已有日期值匹配
  - 输入方式：`fill()` → 验证 → JS 赋值回退
  - 日期面板关闭：Tab 确认 → Escape → 点击空白处
  - **quick_mode**：export_all 场景跳过等待和面板关闭操作，由后续导出按钮点击自动关闭面板
- **下拉选项**（按页面）：
  | 下拉标签 | 适用页面 |
  |---------|---------|
  | 断面名称 | 实时输电断面约束及阻塞、断面约束情况及影子价格、重要通道实际输电情况 |
  | 节点名称 | 实时节点边际电价、日前节点边际电价 |
  | 机组名称 | 日前机组开机安排、机组实际发电曲线 |
  | 联络线名称 | 日前联络线计划 |
  | 通道名称 | 输电通道可用容量 |
  - Element UI 下拉框：面板挂载在 `<body>` 上，需通过可见性检查定位当前打开的面板，避免混入其他面板的选项
  - FineReport combo 控件：优先通过 JS API (`getItems()`) 获取选项，回退到 DOM 操作
- **每页条数**：断面约束、输变电设备检修计划、输电通道可用容量（10/20/30/40/50）
  - FineReport 通过 `PAGESIZE` widgetname 控件设置
  - Element UI 通过分页组件下拉框设置

#### 4.1.3 日期范围处理（重要）
- 配置日期范围：默认 2025-01-01 至当前日期
- **【关键】** 因多数页面仅有单日期选择，实现**按日迭代**：在指定日期区间内逐日设置日期并点击查询，以覆盖整段时间
- **增量更新**：通过检查已存在的 CSV 文件自动跳过已爬取日期

#### 4.1.4 查询与导出

**查询按钮适配：**
- Element UI：`<button>` 元素，文字可能含空格（如"查 询"）
- FineReport：`<div widgetname^="SEARCH">`，widgetname 以 SEARCH 开头（实际有 SEARCH、SEARCH_C、SEARCH_C_C 等变体）

**导出方式：**
- **【优先】** 若页面提供「原样导出」或「导出」按钮，**优先使用该功能**获取数据
- 通过 Playwright 下载事件（`page.expect_download`）捕获文件，主 Page 监听下载事件
- 支持按钮文字空格变体（如"导 出"、"导出"）
- FineReport 导出按钮：`button.fr-btn-text.x-emb-excel`

**export_all 全量导出模式：**
- 部分页面虽有下拉筛选控件，但导出按钮会一次性导出该日期下所有选项的数据到一个文件
- 适用任务：实时节点边际电价、日前机组开机安排、日前节点边际电价
- 流程：设置日期（quick_mode）→ 直接点击导出 → 若失败则先查询再导出
- 跳过下拉选项获取和逐一遍历，显著减少爬取时间

**导出不可用时的回退：**
- 若导出不可用（如实时市场出清概况无导出按钮），则通过 HTML 表格解析获取数据

#### 4.1.5 分页与滚动
- 支持分页控件：首页、上一页、下一页、末页
  - Element UI：`.el-pagination` 组件
  - FineReport：通过 JS API (`gotoPage`) 或页面导航工具栏按钮
- 部分表格仅有竖向滚动条，需处理**滚动加载**或一次性加载大量行的情况
- 可通过「每页条数」下拉尽量增大单页条数，减少翻页次数

#### 4.1.6 调度与反爬
- 支持可配置的爬取频率（`schedule` 模块，使用 `schedule` 库实现定时调度）
- 合理控制请求间隔（翻页 2s、查询 3s、日期迭代 0.2s），遵守 robots.txt
- 失败自动重试（默认 3 次，间隔 5 秒），重试前自动检测并恢复页面状态

### 4.2 数据提取

#### 4.2.1 表格解析

**标准表格（Element UI）：**
- 使用 BeautifulSoup + lxml 解析 iframe 内的 HTML
- 识别 `<thead>` / `<tbody>` 结构
- 提取表头和所有数据行
- 备用 JavaScript 提取方案（`extract_table_via_js`）

**FineReport 报表表格：**
- 表格 class 包含 `x-table` 或 `REPORT`
- 使用 `tridx` 属性标识行：`tridx="0"` 为表头，`tridx="1"+` 为数据行
- 单元格使用 `<td>` 而非 `<th>`
- 自动检测并优先使用 FineReport 解析，回退到标准解析

#### 4.2.2 特殊数据格式
- **出清概况类（实时/日前市场出清概况）**：
  「出清概况」列为长文本，如「02月04日直调用电实际最大负荷3709.87万千瓦...」，需：
  - 使用正则表达式结构化解析拆分各指标
  - 支持提取的指标：
    | 分类 | 指标 |
    |------|------|
    | 负荷 | 直调用电实际/预测最大/最小负荷(万千瓦) |
    | 外送电 | 外送电最大/最小(万千瓦) |
    | 节点电价 | 出清节点电价最大/最小(元/MWh) |
    | 现货市场 | 现货市场场均电量价格(元/MWh) |
    | 火电机组 | 火电机组运行(台)、运行机组总装机(MW) |
    | 调频 | 调频市场需求最大/最小值(MW) |
    | 中标机组 | 中标机组最多/最少(台)、综合指标平均值 |
    | 边际出清 | 边际出清价格最大/最小(元/MWh) |
    | 开停机 | 火电机组已开(台次)、必开容量(MW)、必停(台次)、必停容量(MW) |

### 4.3 数据处理
- 清洗和规范化提取的数据（去除前后空白、转换数字类型）
- 处理数据类型转换（数字、日期、文本），跳过「序号」列的数值转换
- 处理缺失值（空字符串转为 None）
- 记录「最新更新日期」字段（从页面提取并附加到每行数据）

### 4.4 数据存储
- 以 **CSV** 格式存储（编码 utf-8-sig，兼容 Excel）
- 文件命名：`{数据类别}_{日期}_{其他筛选条件}.csv`
  例：`实时节点边际电价_2026-02-05_节点1206008004.csv`、`日前机组开机安排_2026-02-05_220kV思安光伏电站.csv`
- 按分类目录（现货出清结果/现货实时数据/现货日前信息/综合查询）建立子目录
- 导出文件单独保存在 `data/exports/` 目录
- 文件名使用安全字符（保留中文、字母、数字、连字符、下划线）

### 4.5 错误处理与日志
- 异常捕获与分类（网络超时、iframe detached、导出超时、解析失败等）
- 详细日志（时间、级别、模块、操作信息），支持控制台 + 文件双输出
- 日志文件按大小滚动（默认 10MB，保留 5 个备份）
- 自动重试（默认 3 次，间隔 5 秒），重试前自动检测页面状态
- 导航失败时自动保存诊断截图到 `./logs/debug_*.png`

## 9. 补充说明

### 9.1 页面共性
- 顶部显示单位：MW, MWh, 元/MWh, 元
- 部分页面展示「最新更新日期」，用于增量更新判断
- 多数页面含「原样导出」或「导出」按钮（部分按钮文字含空格），优先作为数据源
- 查询按钮文字也可能含空格（如"查 询"），需同时匹配两种变体

### 9.2 分页情况
- 断面约束：多页（如 31 页），需处理分页，支持设置每页条数
- 输变电设备检修计划、输电通道可用容量：有分页，支持设置每页条数
- 日前备用总量：通常单日单行，无分页
- 节点分配因子：有分页
- 实时/日前市场出清概况：有分页
- 其他部分页面可能仅有滚动条，无分页控件

### 9.3 下拉筛选策略
- 对有下拉的页面（断面名称、节点名称、机组名称、联络线名称、通道名称），需：
  - 获取所有选项（Element UI 从可见面板收集 / FineReport 通过 JS API 或 DOM）
  - 逐个选择并查询/导出
  - 选项变化时能自动适配
- **dropdown_select_none 优化**：实时输电断面约束及阻塞、断面约束情况及影子价格、重要通道实际输电情况、机组实际发电曲线、输电通道可用容量，当下拉含「不选」选项时，仅选择「不选」即可获取全部数据，无需逐一遍历（`dropdown_select_none: true`）
- **export_all 例外**：实时节点边际电价、日前机组开机安排、日前节点边际电价，虽有下拉但导出按钮一次性导出所有数据，跳过下拉遍历

### 9.4 FineReport 特殊处理
- FineReport 报表使用三层 iframe 嵌套，需穿透到最内层
- FineReport 的日期控件响应 Tab/Enter 确认值（区别于 Element UI 的 Escape 关闭面板）
- FineReport 查询按钮 widgetname 前缀为 `SEARCH`，存在多种后缀变体
- FineReport 表格使用 `tridx` 属性区分表头行（最小值）和数据行
