## 二、系统概述

### 2.1 目标与范围

- **业务目标**：自动化爬取山西电力交易平台（SXPX）电力现货市场信息披露下的表格类数据，支持多数据类别、日期范围与增量更新。
- **系统边界**：
  - 通过 **Chrome DevTools Protocol (CDP)** 连接已登录的 Chrome，不负责登录与认证。
  - 目标站点为 SPA（hash 路由），内容区在 iframe 内，存在 Element UI 与 FineReport 两种页面类型。
  - 数据以 CSV 形式落盘，支持导出优先、表格解析回退及出清概况正则解析。

### 2.2 关键约束

- 左侧导航为 **el-tree 树形控件**（非 el-menu），需按「信息披露 → 分类 → 页面」三层展开或综合查询独立导航。
- 功能页面在 **iframe** 内（二层或三层嵌套），所有筛选、导出、分页、解析均在 iframe 上下文中执行。
- 任务开关、日期范围、反爬参数、CDP 地址等均通过 **config.yaml** 配置，代码只读配置，新增任务以改配置为主。

## 三、架构目标与原则

- **模块化**：浏览器控制、导航、筛选、导出、分页、数据提取、存储、日志与解析职责分离，便于单测与替换。
- **可配置**：运行模式、日期范围、任务启用/禁用、反爬间隔、存储路径等统一由配置文件驱动。
- **可扩展**：新增数据类别或页面类型时，优先通过配置与现有 handler 扩展完成，必要时再扩展 handler 的检测与分支逻辑。
- **可观测**：全流程日志、文件滚动、导航失败时自动保存诊断截图（`logs/debug_*.png`），便于远程调试与优化（如 Quick Mode 分析）。

## 六、模块职责与接口

### 6.1 入口层 — main.py

| 职责 | 说明 |
|------|------|
| 配置加载 | `load_config(config_path)`，YAML 解析，缺失时退出 |
| 日期与任务 | `get_date_range(config, args)`：命令行优先于 config；`get_enabled_tasks(config, task_filter)`：支持 `--task` 逗号分隔 |
| 批量查询 | `parse_tieline_batch_file(path)`：日前联络线计划 `--batch-file`，返回 `[(start, end, 联络线名称), ...]` |
| 流程入口 | `run_crawler()`：BrowserManager 上下文内创建 PageCrawler，逐任务调用 `crawl_task()`；`run_validation()`：遍历 data 下 CSV 做校验；`run_schedule()`：按间隔循环执行爬取 |

命令行参数：`--config`、`--task`、`--start`、`--end`、`--validate`、`--schedule`、`--list-tasks`、`--batch-file`。

### 6.2 浏览器层 — crawler/browser.py

| 职责 | 说明 |
|------|------|
| 模式 | **connect**（默认）：CDP 连接已有 Chrome，查找含 `target_url_pattern` 的标签页；**launch**：启动 Chromium，可选 headless/slow_mo |
| 生命周期 | 上下文管理器：`with BrowserManager(config) as browser`，退出时断开连接（connect 不关浏览器） |
| 输出 | 暴露 `browser.page`（Playwright Page），并确保下载目录存在 |

### 6.3 爬取编排层 — crawler/page_crawler.py

| 职责 | 说明 |
|------|------|
| iframe 检测与穿透 | `_get_content_frame()`：扫描主页面 iframe，必要时 `_drill_into_nested_iframe()` 穿透三层（如 FineReport）；返回用于操作的 Frame（ctx） |
| iframe 有效性 | 关键步骤前检测 frame 是否 detached，失效时重新检测并恢复 ctx |
| 页面刷新恢复 | 通过 `_task_iframe_id` 与当前 iframe ID 比对，检测跳回首页后重新导航并恢复 ctx |
| 任务编排 | `crawl_task(task_name, task_config, start_date, end_date, batch_queries=None)`：导航 → 取 ctx → 按任务配置执行日期迭代、下拉/export_all/batch 分支，优先导出再表格解析与分页，出清概况走 parser，最后 storage 保存 |
| 重试 | 默认 `retry_times=3`、`retry_interval=5`，每次重试前检测并恢复页面状态 |

PageCrawler 在构造时创建 Navigator、FilterHandler、ExportHandler、PaginationHandler、DataExtractor、CsvStorage，均共享同一 config 与主 page；筛选、导出、分页、解析等实际操作在 iframe 的 Frame（即操作上下文 ctx）上执行。

### 6.4 业务处理层 — 导航 / 筛选 / 导出 / 分页 / 数据提取

| 模块 | 文件 | 职责概要 |
|------|------|----------|
| 导航 | navigator.py | 侧栏 el-tree：`span[title="..."]` 匹配、展开状态检查（aria-expanded）、综合查询独立结构（顶部标签 + 左侧面板）；导航失败时保存诊断截图到 `logs/` |
| 筛选 | filter_handler.py | 自动检测页面类型（Element UI / FineReport）；日期设置（多层回退、quick_mode 支持）；下拉（Element UI 可见面板 / FineReport JS API 或 DOM）；每页条数；查询按钮适配 |
| 导出 | export_handler.py | 查找并点击「原样导出」「导出」等按钮（含空格变体）；兼容 Element UI 与 FineReport `button.x-emb-excel`；主 Page 监听 download 事件并命名保存 |
| 分页 | pagination.py | Element UI `.el-pagination`；FineReport `gotoPage()` 或工具栏；总页数、翻页、跳转；无分页时滚动加载 |
| 数据提取 | data_extractor.py | 标准表格（BeautifulSoup + thead/tbody）；FineReport `table.x-table`、`tridx` 区分表头/数据行；可选「最新更新日期」；备用 JS 提取 |

### 6.5 存储层 — storage/csv_storage.py

| 职责 | 说明 |
|------|------|
| 目录与命名 | 按 `config.storage.output_dir` 与分类建子目录；文件名 `{任务名}_{日期}_{筛选条件}.csv`，安全字符处理 |
| 增量 | `exists_for_date()` / 等价逻辑：已存在 CSV 则跳过该日，实现增量爬取 |
| 写入 | `save()`：整表写入；`append()`：追加以支持分页合并；编码 `utf-8-sig` |


### 6.6 工具层 — utils

| 模块 | 职责 |
|------|------|
| logger.py | 按 config 的 logging 初始化，控制台 + 文件，按大小滚动（max_size_mb、backup_count） |
| parser.py | 出清概况长文本正则解析为结构化指标；日前联络线计划批量文件解析（两列/三列格式） |
| validator.py | 非空、必填字段、数值范围、日期连续性；CSV 文件级校验（空行、重复等），供 `--validate` 使用 |

## 七、关键流程

### 7.1 单任务爬取主流程

1. **导航**：`navigator.navigate_to_task(task_name, task_config)` — 通过侧栏 el-tree 或综合查询内导航进入目标页面。
2. **获取操作上下文**：`_get_content_frame()` — 检测并穿透 iframe，得到内容区 Frame（ctx），后续筛选、导出、解析均在该 ctx 上执行。
3. **日期迭代**：在 start_date～end_date 内逐日处理；若该日该任务数据已存在（增量检查），则跳过。
4. **按日执行策略**（依任务配置选择其一或组合）：
   - **日前联络线计划 + batch_queries**：按批量文件中的 `(start, end, 联络线名称)` 逐条设置日期与下拉并查询/导出。
   - **export_all**：设置日期（可启用 quick_mode）后直接点击导出，不遍历下拉选项。
   - **dropdown_select_none**：下拉选「不选」获取全量，不逐项遍历。
   - **一般下拉**：获取选项列表，逐项选择并查询/导出。
5. **数据获取**：若任务有导出按钮则通过 `export_handler` 点击导出并接收下载文件；否则由 `data_extractor` 解析表格，有分页时由 `pagination` 翻页并合并数据。
6. **特殊解析**：出清概况类任务使用 `parser.parse_clearing_summary_batch()` 将长文本拆解为结构化行。
7. **持久化**：`storage.save()` 或 `append()` 写入 CSV，目录与命名规则见 6.5 节。

### 7.2 iframe 与页面类型

- **二层 iframe**：主页面 → 内容 iframe（Element UI 页面）。
- **三层 iframe**：主页面 → 中间 iframe（如 id=`pxf-settlement-outnetpub`）→ 内层 iframe（如 id=`iframe`，FineReport）。
- 所有筛选、导出、分页、表格解析均在「当前内容 Frame」上执行；主 page 仅用于侧栏导航、键盘事件和下载监听。
- 检测到 frame detached 或 iframe ID 变化（页面被刷新）时，重新导航并重新执行 `_get_content_frame()` 恢复 ctx。

### 7.3 双页面类型适配

- **Element UI**：`.el-date-editor`、`.el-select`、`.el-pagination`、`<button>`、标准 `<table>`。
- **FineReport**：`.fr-trigger-editor`、`widgetname`、`_g()` JS API、`table.x-table` 与 `tridx`。
- 各 handler 根据页面元素自动判断类型（如是否存在 `.fr-trigger-editor`、`.el-date-editor`），并选用对应的选择器与交互方式。

## 九、配置与扩展点

**配置文件 config.yaml 主要段落：**

- **browser**：mode、cdp_url、target_url_pattern、timeout、download_dir
- **date_range**：start_date、end_date
- **request**：翻页/查询/日期间隔，重试次数与间隔，export_timeout
- **schedule**：是否启用、间隔小时数
- **storage**：output_dir、encoding
- **logging**：level、log_dir、max_size_mb、backup_count
- **tasks**：每任务包括 enabled、category、subcategory（综合查询）、has_export、has_dropdown、dropdown_label、has_pagination、has_page_size、export_type、export_all、dropdown_select_none

**扩展方式：**

- **新增数据类别**：在 `tasks` 下新增或修改条目，综合查询类需配置 `subcategory`；多数情况下无需改代码。
- **新增页面类型**：在 filter_handler、export_handler、pagination、data_extractor 中增加类型检测分支及对应的选择器或 JS API 调用。

## 十、数据流与存储约定

- **原始导出文件**：保存到 `config.browser.download_dir`（默认 `./data/exports`）。
- **结构化数据**：按 `config.storage.output_dir`（默认 `./data`）下分类子目录存放 CSV，命名 `{数据类别}_{日期}_{筛选条件}.csv`，编码 utf-8-sig。
- **增量**：按日期/任务/筛选条件判断文件是否已存在，存在则跳过该单元，实现断点续爬。

## 十一、错误处理与可观测性

- **重试**：请求/导出等失败时按 config 重试次数与间隔重试，重试前可重新检测 iframe 与页面状态。
- **日志**：全流程打点，级别由 config 控制；文件按大小滚动，便于长期运行与问题排查。
- **诊断截图**：导航失败时自动保存到 `logs/debug_*.png`，便于远程排查页面或选择器问题。
- **数据质量**：`--validate` 调用 validator 对已有 CSV 做完整性、字段、数值范围、日期连续性等校验。
